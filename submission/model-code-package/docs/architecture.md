# 技术架构说明

## 1. 产品主链路

```text
本地视频导入
→ 读取真实视频时长
→ ffmpeg 抽取关键帧
→ OCR 提取画面文字
→ 整理 OCR 证据和时间戳
→ 大模型结构化菜谱
→ schema 校验与 normalize
→ 备菜确认
→ 一步一屏跟做
→ 当前步骤 AI 教练问答
→ 完成复盘
```

## 2. 大模型承担的角色

### 非结构化证据 → 结构化菜谱

大模型接收 OCR 文本、时间戳、关键帧列表。它需要输出严格 JSON，包括：

- 菜名；
- 食材和用量；
- 备菜项；
- 步骤标题与说明；
- tips；
- commonMistakes；
- rescue；
- startTime / endTime；
- keyFrameUrl。

如果证据不足，Prompt 要求模型返回 `evidence_insufficient`，不能硬编。

### 当前步骤上下文 → 可执行解释与补救

用户在跟做页提问时，系统注入：

- recipeName；
- currentStep.title；
- currentStep.instruction；
- tips；
- commonMistakes；
- userQuestion。

大模型只围绕当前步骤给简短、可执行、适合厨房现场的回答。

### 完成页复盘

当前完成页复盘是本地 session 模板生成，不调用大模型。它基于真实发生的事件，例如提问、视频回看、计时，生成“小白点评”和“下次提醒”。这是为了演示稳定性，不伪装成模型调用。

## 3. App 自身承担的角色

- 视频文件保存和元数据读取；
- ffmpeg 抽帧；
- OCR 调用；
- OCR 证据清洗、去重、拼接；
- 限制时间轴不得超过真实视频时长；
- schema 校验；
- normalize 模型输出；
- 页面状态执行；
- 高频语音命令本地路由；
- fallback 和错误态展示。

## 4. 为什么命令类语音不走大模型

“下一步”“上一步”“播放视频”“计时三分钟”属于高频、低歧义页面动作。为了降低延迟和提高稳定性，这些命令走本地规则解析。

如果 ASR 文本不是明确命令，则作为用户问题进入当前步骤 AI 教练。
